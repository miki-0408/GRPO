## 1. Dynamic Sampling —— 你已经做了一半

### DAPO 的做法

对每个 prompt 采样 G 条，**如果这一组全对或全错，就丢掉，重新采**。直到凑够一个"每组都有梯度"的 batch。

论文里叫 **dynamic sampling**（动态采样），因为它发生在**训练过程中**，是**在线的**。

### 你已经做的

`filter_data.py` 是它的**离线版**——训练前筛一遍。

| | 你的离线筛选 | DAPO 的动态采样 |
|---|---|---|
| 什么时候做 | 训练前，一次性 | 训练中，每一步 |
| 用什么模型判断 | **固定的初始模型** | 当前的模型 |
| 代价 | 预处理时间 | 每个 step 可能多采几轮 |

### 关键差异（这也是你能写进报告的）

**离线筛选用的是训练开始时的模型**。随着训练推进，模型的准确率会变——原本"刚好一半对"的题可能变成"全对"，**筛选出来的数据会过期**。

**DAPO 的在线版本没这个问题**，因为它每次用当前模型判断。

> 你的实验里其实**已经能看到这个现象**：筛选后的数据，训练后期的 `frac_reward_zero_std` 又升回去了（因为模型变强，有些题从"半会"变成"全会"）。
> **这个观察是你独有的**——它需要一个完整的训练日志才能看出来。

### 读的时候带着这个问题

> DAPO 丢掉全对/全错的组，会不会浪费算力？论文是怎么权衡"丢样本"和"多采样"的？

## 2. Token-Level Loss —— 你已经在源码里碰到过

### DAPO 的做法

**每条序列等权**，而不是每个 token 等权：

```
每条等权（DAPO）:  先对每条序列内部按长度平均，再对所有序列取平均
每 token 等权:     把所有 token 拉平了一起平均
```

### 你已经见过它

在 `grpo_trainer.py` 第 3215 行：

```python
loss = ((per_token_loss * mask).sum(-1) / mask.sum(-1).clamp(min=1.0)).mean()
#         └──── 每条序列内部求平均 ────┘   └─ 再对序列取平均 ─┘
```

**TRL 已经实现了 DAPO 的写法。**

而你手写的版本是：

```python
loss = (per_token * mask).sum() / mask.sum()      # 全局拉平平均
```

### 为什么这个差别重要

一条 300 token 的回答，在你的实现里影响是一条 20 token 回答的 **15 倍**。

**后果**：模型会倾向于优化长回答（因为它们的梯度权重更大）—— **这和你的"回答越训越长"是同一件事的两面**。

### 读的时候带着这个问题

> 为什么"每条等权"更好？论文里有没有对应的消融实验？

## 3. Overlong Reward Shaping —— 你正在被它咬

### DAPO 的做法

对**超长**的回答做奖励塑形，而不是简单截断给 0 分。

论文指出：**简单地给被截断的回答 0 奖励，会给模型错误的惩罚信号**——模型不知道自己是"答错了"还是"太长了"。

### 你遇到的现象

```
completions/max_length = 384（撞上限）
completions/max_terminated_length = 0（没有一条自然结束）
reward = 0
```

**8 条全部被截断 → 全给 0 分 → 组内零方差 → 梯度为 0。**

你当时的处理是 `mask_truncated_completions=True`（**被截断的不参与 loss**）。这比"给 0 分"好，但比 DAPO 的方案粗糙——**你还是没给模型任何关于"长度"的反馈**。

### 读的时候带着这个问题

> DAPO 的"软长度惩罚"和你现在"截断就掩码掉"的区别在哪？各自的代价是什么？

## 4. Clip-Higher —— 你还没遇到，但迟早会遇到

### 背景：熵坍缩

PPO/GRPO 的 clip 是 `[1-ε, 1+ε]`，**上下界对称**。

但这两个界的作用**不对称**：

- **上界**（1+ε）限制"把概率往上推"的幅度
- **下界**（1-ε）限制"把概率往下压"的幅度

当一批样本的**优势全是正数**时，所有 token 的概率都在被推高——**上界很快撞满，只有极少数低概率 token 还能被提升**。久而久之，模型的输出分布越来越尖（**熵坍缩**），不再探索，训练停滞。

### DAPO 的做法

**把上下界解耦**：`[1-ε_low, 1+ε_high]`，让 `ε_high > ε_low`。

给"提高低概率 token"留更大的空间 → 维持探索。

### 你现在的状态

`num_iterations=1` → `old_per_token_logps = None` → **ratio 恒等于 1**（你在 Day 5 观察到的）。

所以 **clip 一行都没生效**，`clip_ratio/*` 全是 0。

**你还没遇到熵坍缩，但也还没真正跑过 PPO 的裁剪机制。**

### 读的时候带着这个问题

> 为什么"提高低概率 token 的空间"需要更大？和一开始讲的优势符号有什么关系？

## 5. 还有一件事：DAPO 去掉了 KL 惩罚

GRPO（R1）的损失里有 `β · D_KL`。**DAPO 把它去掉了。**

论文的理由是：KL 约束会限制模型探索，而他们的实验表明**不加 KL 效果更好**。

### 这解释了你在 TRL 里看到的

`GRPOConfig` 的 `beta` 默认是 **0.0** —— TRL 的默认值跟着 DAPO 走。

而你显式设了 `beta=0.04`（跟你从 R1 学来的）。

> **可以做的对照实验**：`beta=0.04`（你的） vs `beta=0.0`（DAPO 默认）。
> 你的日志里 `eval_kl` 一直在爬（0.003 → 0.03），这正是 KL 惩罚在起作用。去掉它会怎样？

## 7. 你今天可以做的对照实验

**TRL 已经把 DAPO 实现好了** —— 你装的那版 `loss_type` 默认就是 `'dapo'`。

所以对照实验**只改一行**：

```python
# train_trl.py
loss_type="dapo",              # 默认值，DAPO 的 token 级 loss
output_dir=os.path.expanduser("~/grpo_out_dapo"),   # ← 换个目录，别覆盖
```

然后：

```bash
python train_trl.py 2>&1 | tee train_dapo.log
python 03-TRL/compare_runs.py ~/grpo_out ~/grpo_out_dapo
```

**这是你技术报告里最有价值的一组对照**：其他条件完全不变，只换 loss 形式。

> 注意：TRL 的 `loss_type="dapo"` 只切换了 **loss 形式**（token 级归一化）。
> 完整的 DAPO 还包括动态采样、clip-higher、超长塑形 —— 那些要自己配。
> **报告里要把这一点说清楚，别把"换了 loss_type"说成"复现了 DAPO"。**
