# PyTorch 概念地图

> 这份文档回答四个问题：这些概念**是什么**、**和什么有关**、**为什么要学**、**会用到哪里**。
> 配套练习：`pytorch_basics.py`。读完这篇再去做练习，会顺很多。

---

## 0. 先建立全局：PyTorch 只有两件事

抛开所有 API，PyTorch 的核心就两句话：

1. **张量（Tensor）** —— 一个能在 GPU 上做批量运算的多维数组
2. **自动微分（autograd）** —— 自动算出「某个标量对每个张量的梯度」

其余的一切（`nn.Module`、`optimizer`、`DataLoader`、`Trainer`）都是**这两件事之上的封装**。

理解这一点很重要：你不是在学五个互不相干的知识点，而是在学**一条从数据到参数更新的流水线**。

---

## 1. Tensor —— 数据长什么样

### 是什么
多维数组。和 NumPy 的 `ndarray` 几乎同构，但多了两个能力：**能在 GPU 上跑**、**能记录梯度**。

### 为什么需要它（为什么不直接用 Python list）
深度学习 99% 的计算是**矩阵乘法**。矩阵乘有两个特性：

- **可批量**：一次算 64 条样本，和算 1 条的开销差不多（GPU 上尤其如此）
- **可并行**：每个输出元素独立，天然适合 GPU 的上千个核心

Tensor 就是为这两点设计的容器。用 Python list 写循环逐元素算，慢几个数量级。

### 最关键的实践约束
**模型和数据必须在同一个设备上。** 报 `Expected all tensors to be on the same device` 就是这个原因。这是新手最高频的错误。

### 在 GRPO 里用在哪
- 输入：token id `(batch, seq_len)`、attention mask
- 中间：logits `(batch, seq_len, vocab_size)`
- 这些都要 `.to("cuda")`

## 2. autograd —— 怎么自动求梯度

### 是什么
PyTorch 在你做前向计算时，**偷偷记下了一张计算图**；调 `.backward()` 时，它沿这张图反向走一遍，用链式法则算出每个参数的梯度。

### 为什么需要它
训练神经网络 = 反复求「损失对**每一个**参数的偏导」。

- 手推公式？GPT 有几十亿参数，不可能。
- 数值差分（逐个参数微扰）？参数有多少个就要跑多少次前向，慢到不可用。
- **反向模式自动微分**：一次前向 + 一次反向，就得到**全部**梯度。复杂度与参数个数无关。

这是唯一可行的方案，所以它是所有深度学习框架的基石。

### 和你的已有知识的关系
**autograd ≈ 计算图上的数据流分析。**

你编译课做的「建图 → 定义 def/use → 沿图传播信息」，和它是同一套思维，只是传播的是梯度而不是活跃变量。你不是从零学一个新领域，是已有的能力换个应用场景。

### 两个必须记住的行为
1. **梯度会累加，不会覆盖。** 所以训练循环每一步开头都要 `zero_grad()`。忘了它，梯度越攒越大，训练直接崩——这是第二高频的错误。
2. **只有 `requires_grad=True` 的张量才会被追踪。** 模型的参数自动是 `True`，你的输入数据默认是 `False`（不需要就没必要算，省显存）。

### 在 GRPO 里用在哪
`loss.backward()` —— 整个训练的驱动力。GRPO 的 loss 形式和你练习里的 MSE 完全不同，但「前向算 loss → backward 求梯度」这个动作一模一样。

## 3. nn.Module —— 参数怎么组织

### 是什么
一个容器：把一堆层（各自持有参数张量）组织成一个对象，并提供三件事：
- 自动登记所有子模块和参数
- `parameters()` 让你一次拿到全部可学习参数（好交给 optimizer）
- `.to(device)` / `.train()` / `.eval()` 作用于整棵树

### 为什么需要它
你有几千个参数张量。得有个东西：
- 把它们**组织**起来（层 → 网络 → 网络里嵌网络）
- 告诉 PyTorch **哪些张量是"需要训练的参数"**，哪些是常量

不然你只能手工维护一个参数列表，传给 optimizer 时还得自己拼装。

### 两条铁律
- **在 `__init__` 里声明层**，**在 `forward` 里定义计算**。混在一起写是常见错误。
- `super().__init__()` 必须调，否则 PyTorch 追踪不到你定义的层，`parameters()` 会返回空。

### 在 GRPO 里用在哪
**Qwen3 模型本身就是一个 `nn.Module`。** 你之后挂的 LoRA adapter 也是。`.to(device)`、`.parameters()`、`.train()/.eval()` 这些操作会直接作用在它上面。

到 GRPO 那一步你会看到 `model.disable_adapter()` 之类的调用——那就是在同一个 Module 树上切换。

## 4. optimizer —— 梯度怎么用

### 是什么
一个对象，持有「参数列表 + 更新规则」。`step()` 时按规则用梯度更新参数。

### 为什么需要它
autograd 只**给你梯度**。但「拿到梯度之后怎么更新参数」是**另一件独立的事**：

- 最朴素：`w ← w - lr * grad`（SGD）
- Adam：给每个参数维护一阶/二阶动量，自适应调整步长
- AdamW：Adam + 正确的权重衰减

这些都是可替换的策略。optimizer 把「更新规则」封装出来，让你换规则不用改训练循环。

### 一个直觉
`lr`（学习率）是最重要的超参。太大 → 震荡发散；太小 → 收敛慢或卡住。你练习 5 里如果 loss 不降，先怀疑 lr。

### 在 GRPO 里用在哪
AdamW，通常配 `adamw_8bit` 或 `paged_adamw_8bit`（bitsandbytes 的低显存版本——你 8GB 卡上会用得到）。

> 注意：GRPO 里 `optimizer.step()` 更新的是**策略模型**的参数。这和你理解的「用梯度更新参数」完全一致，只是 loss 的来源变成了 RL 的奖励。

## 5. Dataset / DataLoader —— 数据怎么喂

### 是什么
- `Dataset`：定义「第 i 条样本是什么」（实现 `__len__` 和 `__getitem__`）
- `DataLoader`：定义「怎么成批取」（batch 大小、是否打乱、并行预取）

### 为什么需要它
两个职责分离：

- **取一条** vs **怎么批量调度** 是不同的问题
- 大模型训练时，数据加载会成为瓶颈。DataLoader 支持多进程预取——GPU 在算这一批时，CPU 已经在准备下一批

### 在 GRPO 里用在哪
**GSM8K 数据集**。`trl` 会用它构造 prompt 批次，然后送给模型生成回答。

到那一步你会发现 `__getitem__` 返回的是文本而不是张量——因为 tokenize 发生在后面的 collator 里。但**模式完全一样**。

## 6. 训练循环 —— 把上面五件事串起来

这是所有深度学习训练的共同骨架，从线性回归到 GPT：

```python
for epoch in range(N):
    for bx, by in dataloader:              # ⑤ DataLoader 供数据
        bx, by = bx.to(DEV), by.to(DEV)    # ① 搬设备
        pred = model(bx)                   # ③ nn.Module 前向
        loss = loss_fn(pred, by)           #    算损失
        optimizer.zero_grad()              #    清上一步梯度 ← 别忘
        loss.backward()                    # ② autograd 反向求梯度
        optimizer.step()                   # ④ optimizer 更新参数
```

**记住这个骨架，你就能读懂任何训练代码。**

### 它在 GRPO 里长什么样

骨架**一模一样**。GRPO 只改了两个位置：

| 位置 | 你现在写的 | GRPO 里 |
|---|---|---|
| **前向** | `pred = model(bx)` 算一次预测 | **生成 G 条回答**（rollout），再算每条的奖励和优势 |
| **loss** | `nn.MSELoss()` | **策略梯度损失**（带 PPO 裁剪 + KL 惩罚） |
| 其余 | `zero_grad → backward → step` | **完全相同** |

所以 **`GRPOTrainer` 不是魔法**——它就是把上面这个循环，连同「rollout + 策略梯度」一起封装成了一个类。你现在手写的就是它的骨架。

## 7. 你需要学到什么程度

**不需要精通 PyTorch。** 你需要的只是：

- [x] 看懂这条链，知道每个部件**为什么存在**
- [x] 能不看教程写出训练循环骨架
- [x] 遇到 `Expected all tensors to be on the same device` 知道是设备不匹配
- [x] 遇到 loss 不降知道先查 lr 和 zero_grad

至于 `nn.Conv2d`、`nn.LSTM`、分布式、混合精度细节——**遇到再查**，现在不用学。

你的目标不是成为 PyTorch 专家，是**能读懂并改动 trl 的训练代码**。这条链就是那把钥匙。
